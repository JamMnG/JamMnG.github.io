⚙️ 핵심 백엔드 로직 (비동기 처리 및 아키텍처 적용)


from fastapi import APIRouter, HTTPException
from pydantic import BaseModel

# 내부 모듈 (예시)
from services import openai_service
from database import db

router = APIRouter()

# 클라이언트 요청 데이터 모델
class DiaryInput(BaseModel):
    user_id: int
    content: str

@router.post("/api/v1/analyze-emotion")
async def analyze_emotion(diary: DiaryInput):
    """
    사용자의 일기를 받아 AI 감정 분석을 수행하고 결과를 반환 및 저장합니다.
    """
    try:
        # 1. OpenAI API를 비동기적으로 호출 (I/O 블로킹 방지)
        response = await openai_service.get_sentiment_score(diary.content)

        # 2. 분석된 온도(Temperature) 데이터를 DB에 저장
        db.save_temperature(
            user_id=diary.user_id, 
            temp=response.temperature
        )

        # 3. 클라이언트에 결과 반환
        return {
            "status": "success",
            "temperature": response.temperature,
            "feedback": response.feedback
        }
        
    except Exception as e:
        # TODO: 실제 운영 환경에서는 e를 로깅 시스템(ex. Sentry)에 기록
        raise HTTPException(status_code=500, detail="서버 오류가 발생했습니다.")

💡 기술 적용 포인트 (Key Achievements)

⚡ 비동기(Async) 처리로 병목 현상 해결

외부 AI API(OpenAI)를 호출할 때 발생하는 네트워크 대기 시간(I/O Bound) 동안 서버의 스레드가 멈추지 않도록 async/await를 적용했습니다. 이를 통해 다수의 사용자가 동시에 일기를 분석 요청하더라도 서버가 블로킹(Blocking)되지 않고 높은 동시성(Concurrency)을 유지하도록 설계했습니다.[cite: 4]

🧩 관심사의 분리 (Separation of Concerns)

라우터(Controller) 내부에 복잡한 AI 호출 로직이나 DB 쿼리를 직접 작성하지 않고, openai_service와 db 모듈로 분리하여 코드의 가독성과 유지보수성을 높였습니다.[cite: 4]

🛡️ Pydantic을 활용한 데이터 검증

FastAPI의 장점인 Pydantic 모델(DiaryInput)을 활용해 클라이언트로부터 들어오는 데이터의 타입과 유효성을 자동으로 검증하도록 구현했습니다.[cite: 4]
